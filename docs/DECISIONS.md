# Decisions and deviations

Format: **ID — decision** · reason.

**D-01 — Free and client-first.** No accounts, sign-ins, trial limits or paid tiers; no separately hosted backend and no database. Statement PDFs and extracted data are processed on the user's device and never uploaded; the server renders UI and handles only non-sensitive things (a theme cookie). The earlier paid-product mechanics were removed in the v2 audit, and a test fails if app source contains commerce or separate-backend vocabulary.
**D-02 — A standard Next.js 16 server build, deployed on Vercel or any Node host.** `npm run dev`, `npm run build`, `npm run start`; no `output: 'export'` (a test forbids it). Server Components and SSR render pages, layouts, guides and metadata; the workbench (`/app`) is a small Client Component because it needs Web Workers, canvas, IndexedDB and drag-and-drop. One Server Action (D-22) and one API route (`/api/health`). This replaces the earlier decision to ship a fully pre-built, file-only site: the requirement was a professional Next.js application using SSR, CSR, Server Components and Server Actions, with no separate backend, rather than a hosting model.
**D-03 — Both `dev` and `build` use webpack (`next dev --webpack`, `next build --webpack`).** (a) Turbopack's worker loader keeps its bootstrap config in the URL fragment, which service-worker-served responses drop, so the parse worker died for returning users (found by the offline E2E test); re-testing Turbopack for production is optional and was not done. (b) The offline precache list is emitted by a webpack plugin in `next.config.mjs`. Next.js 16 refuses to run `next dev` or `next build` under Turbopack when a `webpack` config exists, so `npm run dev` failed until `--webpack` was added; a test now asserts both scripts carry the flag. Using one bundler for dev and production also keeps worker behaviour identical.
**D-04 — pdf.js 6.5.438: the modern build in the browser, the legacy build only in Node tooling; the preview worker is a bundler-emitted asset.** Parsing runs in our own Web Worker using pdf.js's in-thread worker (`globalThis.pdfjsWorker`, so no nested worker); page rendering uses pdf.js's own worker, referenced as `new URL('pdfjs-dist/build/pdf.worker.min.mjs', import.meta.url)`. The bundler resolves it against the installed package and emits a hashed, immutable file on our own origin (the workbench policy forbids a CDN), so the library and its worker cannot drift apart, it is in the precache list automatically, and there is no copy script, no `predev`/`prebuild` hook and no generated `public/pdfjs/`. The modern build has no polyfills and needs ES2026 features (`Map.prototype.getOrInsertComputed` and others); the **supported floor is Chrome/Edge 145, Firefox 144, Safari/iOS 26.2** (compatibility tables, November 2026). The required features were found by removing each one in Chromium for the sample statement (in 6.5.438 all four are needed on the main thread, and in the workers `Promise.try`, `Uint8Array.prototype.toHex` and `Promise.withResolvers`, but not `getOrInsert`; the realm split was different in 6.4.299, which is why the page checks all four and why `tools/check-browser-support.mjs` must be re-run on every pdfjs-dist upgrade); other code paths (for example unusual PDF content) might need more and were not exercised. `src/adapters/pdf/browserSupport.ts` checks them and an older browser gets a clear message (banner and per-file error) instead of "this file could not be read". The earlier choice of the legacy build existed only to support browsers a few releases old; it was dropped on the explicit decision to target current browsers. **Cost:** people on older browsers (for example iPhones that cannot update past iOS 18, or Samsung Internet) cannot use the app. **Node** keeps the legacy build (`tools/pdfNode.ts`) because pdf.js itself says to use it there (the modern build prints a warning) and Node 22 lacks the newer APIs; the browser bundle is therefore tested by E2E, not by the Node integration tests. pdfjs-dist 6 requires Node ≥ 22.13, so `engines.node` says so. No fetching of fonts/cMaps (blocked by the workbench policy), so the preview falls back to system fonts.
**D-05 — Nonce-based CSP from `src/proxy.ts`, chosen per route; `/sw.js` deliberately gets a different policy.** Scripts need the per-request nonce (plus `'strict-dynamic'`); no `'unsafe-inline'`/`'unsafe-eval'` in production. `/app` gets `connect-src 'none'` and `form-action 'none'`; other pages get `'self'` for those (Next.js navigation payloads and Server Actions need it). Per-request nonces force dynamic rendering (`await connection()` in the root layout). A service worker inherits the CSP of its own script response, so `/sw.js` has its own header policy. The builder is a pure function with unit tests (`src/lib/csp.ts`).
**D-06 — zod in `jitless` mode.** zod 4's JIT uses `new Function`, which the CSP forbids (found by the E2E violation listener).
**D-07 — Custom ~150-line XLSX writer on `fflate` instead of a spreadsheet library.** Needs live formulas with cached values, tiny bundle, exact decimals. Verified with openpyxl and LibreOffice recalculation. **Not tested in Microsoft Excel.**
**D-08 — Sign convention: inflow positive, outflow negative for banks *and* cards; balances stored as printed.** Matches OFX; reconciliation has one orientation switch.
**D-09 — No silent corrections.** The only automatic fix is flipping all signs when that provably reconciles; it and the balance-pair search are recorded under "notes about how this file was read".
**D-10 — Persistence is opt-in; a project is a client profile; PDFs stored only on request; wipe deletes everything.** It lives in the browser (IndexedDB behind the `ProjectRepository` port); there is no server-side saving.
**D-11 — Samples ship as a base64 module, not files.** `fetch` is blocked on `/app` by `connect-src 'none'`.
**D-12 — Evaluation protocol.** 11 layouts were tuned against; 4 *held-out* layouts were written afterwards. First run: 2/4 failed (lone "Posting Date" header; card statements printing charges negative). Both were fixed, so those layouts are no longer pristine; reported accuracy uses fresh seeds (201–210) and says so (ACCURACY.md).
**D-13 — Tooling pins:** Next.js 16.4.6 (16.4.2 carried a moderate `npm audit` advisory; 16.4.6 clears it), TypeScript 5.9.3 (not 7), ESLint 9 (jsx-a11y; `npm ci` prints an end-of-support notice), Playwright 1.65.1, Tailwind 4.3.5, Vitest 5.1.1. The `overrides` entry `@typescript-eslint/typescript-estree → minimatch ^11.0.1` fixes the one remaining audit root cause (D-25).
**D-14 — Custom ARIA grid on TanStack Virtual** rather than a data-grid library: full control of roving tabindex, in-cell editing and PDF linkage; axe + keyboard E2E cover it.
**D-15 — OFX 1.0.2 SGML (not 2.x XML); `INTU.BID` default 3000 and user-configurable; FITID = 24-char hash; NAME ≤ 32, MEMO ≤ 255; noon-GMT dates; deterministic output.** Real QuickBooks/Xero imports not tested.
**D-16 — Design system: Geist + neutral tokens + one accent, Tailwind v4 with cascade layers.** Chosen from the evidence in AUDIT.md §2. Component class names must not collide with Tailwind utilities (`.grid`, `.grow` and `.container` did; renamed). Blur and mask effects were removed after measuring a large Lighthouse cost under throttling.
**D-17 — SEO/social on server-rendered HTML:** `metadataBase` + `title.template`; file-convention OG/Twitter images (rendered from HTML by `tools/make-og.mjs`); pages that set their own `openGraph` repeat the image because Next replaces rather than merges it; `/app` is `noindex` (via meta, not a robots Disallow); `sitemap.ts`, `robots.ts` and `manifest.ts` are prerendered at build time (the build output marks them static; they use no request data); JSON-LD `WebApplication`/`TechArticle`/`BreadcrumbList`. Canonical and social URLs come from `NEXT_PUBLIC_SITE_URL` or `VERCEL_PROJECT_PRODUCTION_URL` (`src/config/site.ts`).
**D-18 — Performance under dynamic rendering:** the workbench shell is server-rendered (real HTML first paint); the workbench, secondary views, dialogs and the export engine load on demand; only the UI font is preloaded (the mono font is lazy); the service worker is registered only from the workbench, after load and idle, and does its caching off the main thread. No heavy module may be executed on the main thread just to warm a cache: an earlier attempt did, and it cost mobile Total Blocking Time.
**D-19 — MIT licence.** A permissive licence maximises auditability of the privacy claims.
**D-20 — Not built (roadmap):** offline OCR for scanned PDFs (needs tesseract.js + data + a WASM CSP allowance, verified on scanned samples), passphrase lock for saved projects, real-bank layout guides (bank-specific claims could not be verified).
**D-21 — The workbench is entered with a plain `<a>` (hard navigation), never `next/link`.** A client-side navigation would keep the marketing page's weaker policy; the strict `/app` policy only applies to a full page load. An E2E test covers it.
**D-22 — Theme preference is a cookie changed by a Server Action.** `cycleTheme` cycles `ll-theme` (`system`/`light`/`dark`); the root layout reads it server-side, so there is no flash and no inline script, and the toggle works with JavaScript disabled (E2E-tested). In `/app` the toggle is client-only (writes the same cookie) because the policy forbids Server Actions there. Server Actions never receive statement data.
**D-23 — `Referrer-Policy: same-origin`, not `no-referrer`.** With `no-referrer` browsers send `Origin: null` on same-origin form posts and Next.js rejects the Server Action.
**D-24 — Offline strategy: build-emitted precache list, install-time caching in the service worker, refresh on shell change.** A webpack plugin writes `/_next/static/ll-precache.json` (all client chunks, CSS and fonts). The worker caches it, the `/app/` document with its CSP header (so nonce and header always match) and the pdf.js worker; install fails unless everything was cached, so "Ready offline" is truthful. Because `sw.js` is a static file whose bytes do not change between deploys, an online visit to `/app/` re-precaches when the shell's asset set changes; the previous build's files are kept for one generation. Hashed assets are matched ignoring the query string (a deployment-id suffix must not cause misses; untested on a real Vercel deployment). Rejected alternatives: executing the lazy modules to warm the cache (main-thread cost, D-18) and parsing the webpack runtime's chunk map (fragile).
**D-25 — Scoped `minimatch` override.** `@typescript-eslint/typescript-estree` is forced to `minimatch ^11.0.1`, which clears the audit advisory; a blanket override breaks ESLint, so it stays scoped.
**D-26 — Dependency policy: exact pins, in-range updates, and a one-week age floor for what ships to the browser.** Versions are pinned exactly in `package.json`; updates go through the full suite plus `tools/check-browser-support.mjs` (pdf.js) and `npm audit`. Runtime dependencies are taken at the newest release that is at least a week old (`@tanstack/react-virtual` is on 3.14.26 although 3.14.27 and 3.14.28 appeared within a day of the November 2026 update), because a compromised release is usually noticed within days; dev-only tools take the newest. Deliberately not updated: **ESLint 10** (`eslint-plugin-jsx-a11y` only declares ESLint ≤ 9), **TypeScript 7** (`typescript-eslint` requires TypeScript below 6.1), **`@types/node` 26** (the types track the minimum supported Node, 22), and the test-only majors **jsdom 31** and **@testing-library/jest-dom 8**, which were not evaluated.

## Visual redesign (26–27 November 2026)
**D-27 — Evolve the "calm precision" system, do not replace it.** Geist, the neutral scale, tabular figures, the proof strip and the architecture were right; five things in the baseline screenshots were wrong (chrome height, red meaning two things, the SaaS-kit landing page, a four-column grid squeezed onto phones, the dark palette defined twice). They were fixed on one token set; the identity moves from "indigo SaaS" to "workpaper": ruled rows, a tick margin, a footing with a double-underlined total, ink-blue accent. Evidence and the rejected alternatives are in DESIGN.md §8.1.
**D-28 — No second typeface.** A display serif or grotesque for the marketing headings was considered and rejected: it adds a preloaded font file to the first load and to the offline install, and a high-contrast serif headline is a template of its own. The identity comes from structure (the proof, the margin, the footing), not a font swap. Geist stays; Geist Mono stays lazy.
**D-29 — Colour is status and action only; one `light-dark()` palette.** `tokens.css` defines each colour once as `light-dark(light, dark)` with `color-scheme` selecting the side (system, or the `ll-theme` cookie through `data-theme`); the duplicated dark blocks (one for `data-theme`, one for `prefers-color-scheme`) are gone. Ordinary outflows are ink with a true minus (U+2212), not red, so red keeps one meaning (discrepancy). PDF outlines differ by line style and weight, not hue (D-29 supersedes the old green/purple/indigo field colours), and use fixed `--paper-*` colours because the page is white in both themes. The palette is authored in OKLCH and shipped as hex; `tools/check-contrast.ts` measures 80 pairs and a Vitest test fails the build if one drops below 4.5:1 (text) or 3:1 (UI).
**D-30 — Density follows the pointer, and the stylesheet owns row height.** 32 px rows for fine pointers, 44 px for coarse, 52 px two-line rows in a pane narrower than 560 px (container query, so it also applies when the splitter makes the pane narrow on a desktop). No user density setting (one more control, one more state to test). The virtual lists (workbench grid, merged ledger) read `--row-h`/`--ledger-row-h` from computed style and re-measure on resize, which fixes a latent baseline defect: 36 px rows were laid out at 34 px intervals and overlapped by 2 px. E2E asserts the pitch equals the row height.
**D-31 — The proof bar is a footing.** Opening + in − out = computed closing, then printed closing, with each operator kept with the term it leads so it never dangles at a line end. Report moved from the row toolbar to the proof bar (it is the printable proof, and the toolbar now fits one line on a phone with Export). The stamp stays uppercase: it is a stamp, and the only uppercase label left (column headers are sentence case). The stamp settles once when the verdict changes (keyed by status; workbench only, because on the landing illustration the same animation cost ~100 ms of Total Blocking Time in Lighthouse), and the reduced-motion rule removes it.
**D-32 — Tablet keeps the Rows/PDF switch (breakpoint stays 860 px).** I first intended side-by-side compaction down to ~700 px. The 768 px screenshots decided against it: split evenly, each pane would be about 380 px, below the 560 px where the grid needs two-line rows, and the PDF page is unreadable at that width, whereas one pane at a time shows the page legibly at 100 % and all five columns. The container queries still make a narrowed desktop pane degrade properly.
**D-33 — The landing page shows the proof; nothing else is decoration.** The hero illustration is the product's two proofs side by side (PDF sheet with the row's boxes outlined, ruled rows with ticks, the footing above), built from HTML/CSS so it costs no image bytes and offline needs nothing new, labelled as an illustration of the bundled synthetic sample with five of 24 rows. No eyebrow chip, gradient, window-frame mock, icon tiles, numbered cards for non-sequences, testimonials, logos or counts. The CSP excerpt was corrected: it claimed "every page" and a `sha256` script source; the real policy is per route, with a nonce and `strict-dynamic`, and only `/app/` has `connect-src 'none'`.
**D-34 — Guards and tooling for the new system.** `tools/shots.ts` (screenshot matrix: 34 screens and states × light/dark × 1440/768/390, resumable), `tools/check-contrast.ts` + `tests/unit/design-tokens.test.ts` (palette measurement; also asserts one palette definition and no remote `url()` in styles), `e2e/design.spec.ts` (colour roles, row pitch, window-splitter semantics, narrow layout, reduced motion, forced colours, focus ring). The splitter gained `aria-controls` and Home/End per the APG window-splitter pattern.
